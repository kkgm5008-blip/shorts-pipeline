# 숏폼 자동화 파이프라인 (바이브 코딩 뼈대 버전)

**가장 쉬운 사용법: `run_app.bat` 더블클릭 → 브라우저에서 작업.**
(윈도우 기준. 처음 설치는 한 번 해야 하지만, 그다음부터는 명령어 안 치고
마우스 클릭만으로 씁니다. 아래 "웹앱으로 쓰기" 섹션 참고)

**내 PC가 꺼져 있어도 링크로 언제든 접속하고 싶다면** 아래
"온라인 사이트로 배포하기" 섹션을 참고하세요 (무료로 가능합니다).

내부적으로는 세 개 파일로 구성되어 있습니다.

- `app.py` : **브라우저에서 파일 올리고 버튼 클릭으로 쓰는 웹앱** (추천).
  아래 main.py/autocut.py 기능을 화면 두 개(탭)로 나눠서 그대로 담았습니다.
- `main.py` : 영상 하나를 넣으면 자막 확보 + 맞춤법 검사 + 인트로 체크 +
  숏폼 하이라이트 클립 추출 + 프리미어 마커까지 해주는 파이프라인 (명령어 버전)
- `autocut.py` : **원본(raw) 영상**을 넣으면 무음을 제거하고 재미있는
  부분 위주로 이어붙인 **롱폼 러프컷**을 만들어주는 자동 컷편집 기능 (명령어 버전).
  선택적으로 **레퍼런스 영상**(편집 스타일을 참고할 다른 영상)을 같이
  넣으면 그 영상의 컷 속도(평균 클립 길이)를 참고해서 편집 리듬을 맞춥니다.

`app.py`는 `main.py`/`autocut.py`와 완전히 같은 로직을 씁니다(같은
`modules/` 폴더를 공유). 명령어가 편하신 분은 `main.py`/`autocut.py`를
그대로 쓰셔도 되고, 그게 아니면 웹앱 하나만 쓰셔도 충분합니다.

## main.py 가 하는 일

영상 파일 하나를 넣으면:
1. 자막을 확보하고 (기존 SRT가 있으면 그대로, 없으면 자동 생성)
2. 자막 맞춤법/문법을 검사해서 리포트를 만들고
3. 인트로가 있는지 판단해서 없으면 알려주고
4. 숏폼용 하이라이트 구간을 골라 9:16 세로 영상으로 잘라주고
5. 프리미어 프로에서 바로 쓸 수 있는 마커 파일(CSV)을 만들어줍니다.

**중요:** 이 도구는 영상에 자막을 "굽지" 않습니다. 항상 별도 SRT 파일로
내보내서 프리미어 프로에서 자유롭게 수정할 수 있게 했습니다. 최종 편집은
프리미어에서 하고, 이 도구는 준비/제안 단계를 자동화하는 용도입니다.

## 설치

```bash
cd shorts_pipeline
pip3 install -r requirements.txt
# ffmpeg가 없다면 설치 필요 (mac: brew install ffmpeg / win: choco install ffmpeg)
```

맞춤법 검사에 Claude API를 쓰고 싶다면:
```bash
pip3 install anthropic
export ANTHROPIC_API_KEY="sk-..."
```

## 웹앱으로 쓰기 (추천)

설치(`pip install -r requirements.txt`, ffmpeg PATH 등록)는 한 번만 하면 됩니다.
그 이후로는:

**윈도우**: `shorts_pipeline` 폴더 안의 **`run_app.bat`을 더블클릭**하세요.
검은 창이 하나 뜨고 잠시 후 브라우저가 자동으로 열립니다. (이 검은 창은
웹앱이 켜져 있는 동안 계속 떠 있어야 하니 닫지 마세요. 다 쓰시면 그냥
닫으면 웹앱도 꺼집니다)

**맥/리눅스 또는 직접 명령어로 실행하고 싶다면**:
```bash
python3 -m streamlit run app.py
```

브라우저가 열리면 `http://localhost:8501` 주소로 접속됩니다 - 이건 이
컴퓨터 안에서만 열리는 주소라 인터넷에 공개되는 게 아니니 안심하고
쓰셔도 됩니다.

화면에 탭이 두 개 있습니다.

- **📹 숏폼 만들기**: 영상(+선택적으로 자막) 올리고 실행 버튼 누르면
  자막/맞춤법 리포트/인트로 판단/숏폼 클립/프리미어 마커가 한 번에
  나옵니다. 클립은 그 자리에서 미리보기도 되고, 개별 다운로드나 전체
  zip 다운로드도 가능합니다.
- **✂️ 자동 컷편집**: 원본 영상(+선택적으로 레퍼런스 영상, 자막) 올리고
  실행하면 무음 제거 + 재미있는 부분 위주로 이어붙인 완성 영상과
  프리미어용 EDL/구간 목록이 나옵니다.

옵션(클립 길이, 맞춤법 엔진, 무음 기준 등)은 각 탭의 "⚙️ 옵션" 부분을
펼치면 조절할 수 있고, 안 건드리면 기본값으로 돌아갑니다.

## 온라인 사이트로 배포하기 (PC가 꺼져 있어도 링크로 접속)

위의 `run_app.bat`은 **내 PC가 켜져 있을 때만** 열리는 링크입니다. PC를
꺼도 언제든 접속되는 진짜 온라인 사이트로 만들려면, 이 앱을 클라우드
서버에 올려둬야 합니다. 무료로 할 수 있는 방법을 정리했습니다.

**미리 알아두실 점**: 영상 편집 작업(자막 자동 생성, 영상 렌더링)은
컴퓨터 자원을 많이 씁니다. 아래 무료 방법은 사양이 넉넉하지 않아서
짧은 영상은 잘 되지만, 길거나 큰 영상은 느리거나 실패할 수 있습니다.
실제로 무거운 영상을 자주 돌리실 거면, 맨 아래 "유료로 제대로 하려면"
부분도 참고해주세요.

### 방법: Streamlit Community Cloud (무료)

1. **GitHub 계정 만들기** (이미 있으면 생략): [github.com](https://github.com) 에서 가입
2. **새 저장소(repository) 만들기**: GitHub 로그인 후 오른쪽 위 **+** 버튼 → **New repository**
   → 이름은 아무거나(예: `shorts-pipeline`) → **Create repository**
3. **이 폴더 파일들을 통째로 업로드**: 방금 만든 저장소 페이지에서
   **"uploading an existing file"** 링크 클릭 → `shorts_pipeline` 폴더 안의
   파일/폴더들을 전부 끌어다 놓기 (드래그&드롭) → 아래 **Commit changes**
   (터미널/git 명령어 필요 없이 브라우저에서 다 됩니다)
   - `test_assets` 폴더의 영상 2개는 용량만 차지하니 안 올려도 됩니다.
4. **Streamlit Community Cloud 가입**: [share.streamlit.io](https://share.streamlit.io) 접속 →
   **"Sign in with GitHub"**로 로그인 (별도 가입 절차 없이 GitHub 계정으로 바로 됨)
5. **New app** 클릭 → 방금 만든 저장소 선택 → Main file path에 **`app.py`** 입력 → **Deploy**
6. 몇 분 기다리면 빌드가 끝나고 `https://아무개-shorts-pipeline.streamlit.app`
   같은 링크가 생깁니다. **이 링크가 앞으로 계속 쓰실 주소예요.** 즐겨찾기
   해두시면 됩니다.

**비밀번호 걸기 (권장)**: 이 링크는 아는 사람 누구나 들어와서 쓸 수
있습니다. 남이 함부로 못 쓰게 하려면, Streamlit Cloud 앱 관리 화면에서
**Settings → Secrets**로 들어가서 아래처럼 입력하고 저장하세요.
```
APP_PASSWORD = "원하는_비밀번호"
```
저장하고 앱이 재시작되면, 링크로 들어갔을 때 비밀번호를 먼저 물어보게
됩니다. (로컬 `run_app.bat`으로 쓸 때는 이 설정이 없어서 자동으로
비밀번호 없이 그냥 열립니다.)

**무료 버전에서 주의할 점**:
- 한동안 아무도 안 쓰면 앱이 "잠들어서", 오랜만에 링크로 들어가면
  다시 깨어나는 데 1분 정도 걸릴 수 있습니다 (정상입니다, 기다리시면 됨).
- STT 모델은 옵션에서 **tiny나 base**로 골라 쓰시는 걸 추천합니다
  (small 이상은 무료 서버 메모리로 버거울 수 있음).
- 업로드 파일 크기는 500MB로 설정해뒀는데, 그래도 처리 자체가
  느릴 수 있습니다 (긴 영상은 몇 분씩 걸릴 수 있어요).

### 유료로 제대로 하려면

나중에 무료 버전이 답답해지면, Render.com이나 Railway.app 같은
곳에서 월 5~7달러 정도의 서버를 빌려서 같은 앱을 올리면 훨씬
빠르고 안정적으로 씁니다. 이건 서버 설정이 조금 더 필요한
작업이라, 필요해지시면 그때 다시 도와드릴게요.

## 사용법 - main.py (명령어로 쓰고 싶은 경우)

```bash
# 자막 없는 영상 (자동 생성)
python3 main.py --video my_video.mp4

# 이미 자막 파일이 있는 경우
python3 main.py --video my_video.mp4 --srt my_video.srt

# 옵션 조절
python3 main.py --video my_video.mp4 \
  --clip-len 20 --top-n 5 \
  --whisper-model small \
  --spellcheck-backend auto \
  --fps 30
```

## 사용법 - autocut.py (명령어로 쓰고 싶은 경우)

```bash
# 레퍼런스 없이: 무음만 제거
python3 autocut.py --video raw.mp4

# 레퍼런스 영상의 컷 리듬을 참고해서 편집
python3 autocut.py --video raw.mp4 --reference cool_reference.mp4

# 자막이 있으면 '재미 점수' 계산에 자막 밀도도 반영됨
python3 autocut.py --video raw.mp4 --srt raw.srt --reference cool_reference.mp4

# 최종 길이를 90초로 압축 (점수 낮은 구간부터 제거)
python3 autocut.py --video raw.mp4 --reference cool_reference.mp4 --target-duration 90

# 무음 판정이 너무 민감하거나 둔감하면 조절
python3 autocut.py --video raw.mp4 --noise-db -30 --min-silence-len 0.7
```

### autocut.py 결과물 (output/ 폴더)

| 파일 | 설명 | 프리미어에서 쓰는 법 |
|---|---|---|
| `{name}_autocut.mp4` | 무음 제거 + 재미있는 부분 위주로 이어붙인 완성 영상 | 그대로 타임라인에 올려서 씀 (가장 확실한 방법) |
| `{name}_autocut.edl` | 컷 구간을 원본 영상 기준 in/out으로 정리한 EDL | File > Import로 불러오면 새 시퀀스 생성 (실험적, 아래 주의사항 참고) |
| `{name}_autocut_segments.csv` | 유지된 구간과 점수/사유 목록 | EDL이 안 맞을 때 이 표를 보고 수동으로 인/아웃 입력 |
| `{name}_autocut_report.txt` | 원본 대비 얼마나 줄었는지 요약 | 참고용 |

**EDL 관련 주의사항**: EDL은 컷 구간만 담은 단순한 인터체인지 포맷이라
프리미어 버전/설정에 따라 임포트 시 "미디어를 찾을 수 없음" 창이 뜰 수
있습니다. 그때 원본 `raw.mp4` 파일을 지정해주면 연결됩니다. 그래도 잘
안 맞으면, 가장 확실한 방법은 그냥 `{name}_autocut.mp4`(이미 렌더링된
완성 영상)를 타임라인에 올리고 거기서부터 다듬는 것입니다.

## 결과물 (output/ 폴더)

| 파일 | 설명 | 프리미어에서 쓰는 법 |
|---|---|---|
| `{name}.srt` | 전체 자막 | File > Import 또는 캡션 트랙으로 임포트 |
| `{name}_spellcheck_report.txt` | 맞춤법 검사 결과 | 참고용 텍스트, 자막 수정 시 참고 |
| `{name}_shorts/*.mp4` + `*.srt` | 숏폼 하이라이트 후보 (9:16) + 구간별 자막 | 새 시퀀스로 임포트 후 자막 붙이기 |
| `{name}_vertical.mp4` | 전체 영상 9:16 버전 | 그대로 사용하거나 추가 편집 |
| `{name}_markers.csv` | 인트로 경고/하이라이트/맞춤법 이슈 마커 | Marker 패널 우클릭 > Import Markers |
| `{name}_markers_readable.txt` | 마커를 사람이 읽기 좋게 정리한 버전 | CSV 임포트 안 맞으면 보고 수동 입력 |

## 알아두면 좋은 점 (뼈대 버전의 한계)

- **자막 자동 생성(STT)**: `faster-whisper`를 씁니다. CPU에서도 돌아가지만
  영상이 길면 시간이 꽤 걸립니다. GPU가 있으면 `modules/transcribe.py`의
  `device="cpu"`를 `"cuda"`로 바꾸면 훨씬 빨라집니다.
- **맞춤법 검사**: 기본은 네이버 맞춤법 검사기를 씁니다(인터넷 필요, 무료,
  API 키 불필요). 네이버 접속이 막힌 환경이면 자동으로 오프라인 규칙 기반
  검사로 대체되는데, 이건 흔한 오타 몇 가지만 잡는 수준이라 정확도가 낮습니다.
  더 똑똑한 문맥 기반 검사를 원하면 `--spellcheck-backend claude` +
  `ANTHROPIC_API_KEY` 설정을 추천합니다.
- **인트로 감지**: "장면 전환 + 첫 대사 시작 시점"이라는 두 가지 신호로
  추정하는 휴리스틱입니다. 100% 정확하지 않으니 결과를 참고용으로만
  쓰고, 애매하면 직접 눈으로 확인하세요.
- **숏폼 하이라이트 선정**: 지금은 "자막 글자 수 밀도 + 느낌표/물음표"로
  점수를 매기는 단순한 방식입니다. 실제로 써보면서 어떤 구간을 더/덜
  뽑아야 하는지 감이 잡히면, `modules/shorts.py`의 `select_highlights`
  점수 계산 로직에 원하는 조건(예: 특정 키워드, 웃음 소리 등)을 추가해가면
  됩니다. 이게 "뼈대"인 이유이기도 합니다 - 실제로 써보면서 같이 다듬어가면 됩니다.
- **마커 CSV의 타임코드**: 프리미어 시퀀스의 시작 타임코드가 `00:00:00:00`이
  아니거나 fps가 다르면 마커 위치가 어긋날 수 있습니다. `--fps` 옵션을
  시퀀스 설정과 맞추고, 안 맞으면 `_markers_readable.txt`를 보고 수동으로
  입력하세요.
- **autocut.py의 '레퍼런스 스타일 반영'**: 레퍼런스 영상의 실제 컷 내용을
  따라하는 게 아니라, "컷이 평균 몇 초마다 바뀌는지"만 뽑아서 원본 영상의
  긴 발화 구간을 그 길이에 맞춰 앞부분만 잘라 쓰는 단순한 방식입니다.
  그래서 문장 중간에서 잘릴 수 있습니다. 정교한 스타일 복제가 필요하면
  `modules/reference_style.py`를 발전시켜서 컷 타이밍뿐 아니라 자막
  리듬, 컷 사이 침묵 길이 같은 특징을 더 반영하면 됩니다.
- **autocut.py의 '재미 점수'**: 자막이 있으면 글자 밀도 + 느낌표/물음표를,
  없으면 오디오 음량만 봅니다. 웃음소리, 박수, 갑작스런 톤 변화 같은 건
  아직 반영하지 않으니, 실제로 써보고 어떤 구간이 자꾸 잘못 골라지는지
  보면서 `modules/autocut.py`의 `build_segments` 점수 계산 로직에
  조건을 추가해가면 됩니다.

## 테스트용 샘플

`test_assets/` 폴더에 설치 확인용 합성 영상이 들어있습니다.

```bash
# main.py 스모크 테스트
python3 main.py --video test_assets/test_video.mp4 --srt test_assets/test.srt --skip-full-vertical

# autocut.py 스모크 테스트 (무음 구간이 섞여 있는 테스트 영상)
python3 autocut.py --video test_assets/test_video_silence.mp4
```
